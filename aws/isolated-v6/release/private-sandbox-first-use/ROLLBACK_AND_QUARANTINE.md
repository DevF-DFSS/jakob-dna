# Stop, quarantine and recovery for the first private sandbox

**No rollback has been exercised.** This is a future sequence requiring the exact actor/phase authorization. Retention and CloudFormation rollback are mechanisms to test, not proof of recovery.

- **Before bootstrap:** missing first writer, approval, role trust, exact hash or collision check means no AWS write. Current state is BLOCKED.
- **Bootstrap partial create or unexpected resource:** stop stack progression and artifact publication. The new API has no intended stage/route; empty bucket has public access blocked. Read stack events/resource metadata and bucket/API configuration without payloads. Retain the resources; do not blindly delete retained bucket/API or fall back to legacy. Obtain a separate time-limited approved recovery actor and decide repair/quarantine from actual state. Expiry is never extended automatically.
- **Failed readback:** treat missing or contradictory observation as UNKNOWN. Do not install authority or create runtime. Revalidate operator and resource names; if a policy unexpectedly exposes the API/bucket, request independent emergency containment. No root default.
- **Authority/runtime failure:** prohibit ingress stack creation. Confirm legacy identity-side fence and maximum boundaries have not been removed or weakened. Retain table and artifact bucket. A CloudFormation rollback can fail or remove policy protection; record events, stop, and use fresh bounded recovery authorization rather than a standing admin role. PR16 DescribeStacks delete-handler remains unresolved until safely observed.
- **TEST ingress failure or boundary negative failure:** quarantine **ingress first** through the separately controlled ingress stack/actor. Verify routes/stage stop serving; if CloudFormation cannot remove them, escalate to a separately authorized exact API child-resource repair. Then move runtime back to a reviewed CLOSED artifact/alias or wait for the absolute TEST capability expiry while denying further use. An old active version may otherwise remain reachable through a retained ingress. Record status and fresh evidence before any retry.
- **Provider/auth/identity mismatch, unauthorized direct invoke, role reuse, wrong source context or cross-tenant write:** halt tests, isolate ingress, preserve logs/config metadata, and treat as an A/B boundary failure. Do not rationalize it as an application bug.
- **Manual expiration:** record absolute policy and capability deadlines, account for propagation and operations already in flight. Trust removal alone does not revoke issued sessions. A failed window requires a newly approved recovery window, not automatic renewal.

The stage, runtime and bootstrap have different actors. A runtime actor cannot unilaterally change the API stage; an ingress actor cannot change the runtime code. Their joint authorized recovery still needs fresh human authority. The current account has no usable non-root recovery operator; this sequence is a specification, not an installed fallback.
